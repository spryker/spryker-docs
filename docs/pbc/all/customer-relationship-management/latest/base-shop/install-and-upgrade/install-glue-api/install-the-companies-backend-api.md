This document describes how to install the [Companies Backend API](/docs/pbc/all/customer-relationship-management/base-shop/companies-backend-api.html), which exposes company data at `/companies` on the Glue Backend API.

## Prerequisites

Install the required features:

| NAME | VERSION | INSTALLATION GUIDE |
| --- | --- | --- |
| Spryker Core | {{page.release_tag}} | [Install the Spryker Core feature](/docs/pbc/all/miscellaneous/latest/install-and-upgrade/install-features/install-the-spryker-core-feature.html) |
| Company Account | {{page.release_tag}} | [Install the Company Account feature](/docs/pbc/all/customer-relationship-management/base-shop/install-and-upgrade/install-features/install-the-company-account-feature.html) |

Step 1 installs the remaining modules the API depends on, so you do not have to install them beforehand.

The API resource is generated by API Platform. If your project does not use API Platform yet, follow [Integrate API Platform](/docs/integrations/spryker-api/migrate-from-glue-to-api-platform/integrate-api-platform.html) before you continue.

{% info_block warningBox "Plan for a Symfony upgrade" %}

The feature's dependencies resolve against Symfony 7. On a project still running Symfony 6.4, installing it upgrades the Symfony components project-wide—`symfony/console`, `symfony/http-foundation`, `symfony/security-*`, `symfony/translation`, and others move from 6.4 to 7.x, and `symfony/security-guard`, which was removed in Symfony 7, is dropped.

This affects the whole project, not just the Glue Backend application. Treat this installation as a Symfony major upgrade: run it on a branch, and verify your Yves, Zed, and Back Office applications before merging. Check what Composer intends to change before you commit to it:

```bash
composer update spryker-feature/customer-experience-management --with-dependencies --dry-run
```

{% endinfo_block %}

## Install feature core

### 1) Install the required modules

Install the feature using Composer:

```bash
composer require spryker-feature/customer-experience-management --update-with-dependencies
```

{% info_block warningBox "Version constraint" %}

`spryker-feature/customer-experience-management` is versioned independently of the Spryker release tags, so a constraint such as `{{page.release_tag}}` does not resolve. Let Composer pick the latest version it can, or pin the one you have qualified.

{% endinfo_block %}

{% info_block warningBox "spryker/api-platform" %}

The Customer Experience Management feature declares `spryker/api-platform` as a *suggested* dependency, not a required one, so Composer does not pull it in. Check whether your project already requires it:

```bash
composer show spryker/api-platform
```

If it does not, install it as well—without it, the `/companies` resource is never registered and the endpoint returns `404`:

```bash
composer require spryker/api-platform
```

If your project already requires it, leave that constraint alone rather than re-requiring it at a lower version.

{% endinfo_block %}

### 2) Check the API Platform configuration

The resource schema ships inside the installed package, at `vendor/spryker-feature/customer-experience-management/resources/api/backend/companies.resource.yml`. The generator finds it as long as the Glue Backend application is configured for the `backend` API type and scans the vendor directory the feature is installed into.

Open **config/GlueBackend/packages/spryker_api_platform.php** and check two settings:

```php
$sprykerApiPlatform->apiTypes(['backend']);

// Only if your project overrides the defaults.
$sprykerApiPlatform->sourceDirectories([
    'src/Pyz',
    'vendor/spryker',
    'vendor/spryker-shop',
    'vendor/spryker-feature',
]);
```

{% info_block warningBox "Do not replace this file" %}

`sourceDirectories` is optional and defaults to the directories Spryker packages are installed into, so most projects need no change here at all. If your project sets it explicitly, **add** `vendor/spryker-feature` to the existing list rather than replacing it—dropping the other entries hides every resource your project already serves.

{% endinfo_block %}

Also confirm that `config/GlueBackend/bundles.php` registers `SprykerApiPlatformBundle` and `ApiPlatformBundle`. If it does not, your project has not adopted API Platform for the Glue Backend yet—see [Integrate API Platform](/docs/integrations/spryker-api/migrate-from-glue-to-api-platform/integrate-api-platform.html).

### 3) Set up the database schema and transfer objects

Apply the database changes and generate the transfer objects:

```bash
docker/sdk console transfer:generate
docker/sdk console propel:install
```

{% info_block warningBox "Verification" %}

Make sure the `spy_company` table has a `uuid` column and that existing rows are backfilled. The UUID behavior fills the column when a company is saved; companies created before the module was installed have an empty `uuid` and cannot be addressed by the API until they are saved again.

{% endinfo_block %}

### 4) Generate the API resources

Clear the Glue Backend cache and regenerate the API resources:

```bash
rm -rf data/cache/GlueBackend/<environment>
docker/sdk cli "GLUE_APPLICATION=GLUE_BACKEND vendor/bin/glue api:generate"
docker/sdk cli "GLUE_APPLICATION=GLUE_BACKEND vendor/bin/glue cache:clear"
```

Replace `<environment>` with your environment name, for example, `development`.

{% info_block warningBox "Verification" %}

Make sure the generated resource class exists at `src/Generated/Api/Backend/CompaniesBackendResource.php`. If it does not, the schema was not discovered—check the `sourceDirectories` setting from step 2.

{% endinfo_block %}

## Verification

Request a Back Office access token as described in [Authenticate as a Back Office user](/docs/pbc/all/identity-access-management/latest/manage-using-glue-api/glue-api-authenticate-as-a-back-office-user.html), then retrieve a company collection:

```bash
curl "https://glue-backend.mysprykershop.com/companies?page[limit]=1" \
  -H "Authorization: Bearer {access_token}" \
  -H "Accept: application/vnd.api+json"
```

The integration is successful when the request returns `200` with a `data` array and a `meta.pagination` object.

Create a company to confirm the write path:

```bash
curl -X POST "https://glue-backend.mysprykershop.com/companies" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/vnd.api+json" \
  -H "Accept: application/vnd.api+json" \
  -d '{"data":{"type":"companies","attributes":{"name":"Acme Corporation"}}}'
```

The request returns `201` with the created company, which is `pending` and inactive.

### Troubleshooting

| SYMPTOM | CAUSE |
| --- | --- |
| `404` on `/companies` | The resource was not generated. Repeat step 4 and confirm that `spryker/api-platform` is installed and `src/SprykerFeature` is in `sourceDirectories`. |
| `401` with error code 001 | The access token is missing, invalid, or expired. |
| `422` with a message such as `name => validation.not_blank` | Validation messages reach the response as untranslated keys. The feature ships its API messages as `data/translation/Api/{locale}.csv` inside the installed package, and they are loaded by `spryker/api-platform`. Update `spryker/api-platform` to the latest version your project supports. |
| `404` with error code 1213 for a company you can see in the Back Office | That company's `uuid` is empty. Save it once in the Back Office to have the UUID behavior fill the column. |
