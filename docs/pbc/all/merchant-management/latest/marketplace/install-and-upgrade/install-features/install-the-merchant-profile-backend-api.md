This document describes how to install the Merchant Profile Backend API, which lets merchant users manage the profile of their merchant and Back Office users manage any merchant profile through the `merchant-profiles` resource of the Backend API.

## Prerequisites

Install the required features:

| NAME | VERSION | INSTALLATION GUIDE |
| --- | --- | --- |
| Spryker Core | {{page.release_tag}} | [Install the Spryker Core feature](/docs/pbc/all/miscellaneous/latest/install-and-upgrade/install-features/install-the-spryker-core-feature.html) |
| Marketplace Merchant | {{page.release_tag}} | [Install the Marketplace Merchant feature](/docs/pbc/all/merchant-management/latest/marketplace/install-and-upgrade/install-features/install-the-marketplace-merchant-feature.html) |

{% info_block warningBox "API Platform required" %}

The `merchant-profiles` resource is generated by API Platform, its endpoints are protected by API Platform security, and the merchant behind a token is resolved by the API Platform request pipeline. The resource is not available on the legacy Glue infrastructure. If your project does not use API Platform yet, follow [Integrate API Platform](/docs/integrations/spryker-api/migrate-from-glue-to-api-platform/integrate-api-platform.html) and [Integrate API Platform security](/docs/integrations/spryker-api/authenticating-and-authorization/integrate-api-platform-security.html) first.

{% endinfo_block %}

Merchant users authenticate with the `merchant-user` scope. To register the plugins that provide it, follow the [Optional: Enable the Backend API authentication](/docs/pbc/all/merchant-management/latest/marketplace/install-and-upgrade/install-features/install-the-marketplace-merchant-feature.html#optional-enable-the-backend-api-authentication) step of the Marketplace Merchant feature installation guide.

## Install feature core

### 1) Install the required modules

Install the required modules using Composer:

```bash
composer require \
  spryker/merchant-profile:"^1.11.0" \
  spryker/merchant-user:"^1.9.3" \
  spryker/api-platform:"^1.30.0" \
  spryker/oauth-backend-api:"^1.8.0" \
  spryker/user:"^3.33.0" \
  spryker/uuid-behavior:"^1.3.0" \
  --update-with-dependencies
```

<details>
<summary>What each version provides</summary>

| MODULE | MINIMUM VERSION | PROVIDES |
| --- | --- | --- |
| spryker/merchant-profile | ^1.11.0 | The `merchant-profiles` resource and the optional `Uuid` feature for `spy_merchant_profile_address` |
| spryker/merchant-user | ^1.9.3 | Resolving the merchant user behind an access token, including merchant users of merchants that are not approved yet |
| spryker/api-platform | ^1.30.0 | The `ROLE_MERCHANT_USER` and `ROLE_BACK_OFFICE_USER` roles derived from the token scopes |
| spryker/oauth-backend-api | ^1.8.0 | The `POST /token` endpoint that issues merchant user and Back Office user tokens |
| spryker/user | ^3.33.0 | Establishing the acting user on Backend API requests |
| spryker/uuid-behavior | ^1.3.0 | The UUID behavior used by the `Uuid` feature |

</details>

{% info_block warningBox "Verification" %}

Make sure the following modules have been installed:

| MODULE | EXPECTED DIRECTORY |
| --- | --- |
| MerchantProfile | vendor/spryker/merchant-profile |
| MerchantUser | vendor/spryker/merchant-user |
| ApiPlatform | vendor/spryker/api-platform |
| OauthBackendApi | vendor/spryker/oauth-backend-api |
| User | vendor/spryker/user |
| UuidBehavior | vendor/spryker/uuid-behavior |

{% endinfo_block %}

### 2) Set up configuration

The API identifies an existing merchant profile address by its UUID. The `spy_merchant_profile_address.uuid` column is provided by the `Uuid` feature of the `MerchantProfile` module, which is disabled by default. Enable it:

**src/Pyz/Shared/MerchantProfile/MerchantProfileConfig.php**

```php
<?php

namespace Pyz\Shared\MerchantProfile;

use Spryker\Shared\MerchantProfile\MerchantProfileConfig as SprykerMerchantProfileConfig;

class MerchantProfileConfig extends SprykerMerchantProfileConfig
{
    public function isUuidEnabled(): bool
    {
        return true;
    }
}
```

You can leave the feature disabled. In that case, addresses can be retrieved and created, but not updated: an update attempt is rejected with the error code `1304`.

### 3) Set up the database schema and transfer objects

Apply the database changes and generate the entity and transfer classes:

```bash
console cache:class-resolver:build
console propel:install
console transfer:generate
```

If the installation already holds merchant profile addresses, fill the new column. The UUID behavior sets it for new rows only, and an address without a UUID cannot be updated through the API:

```bash
console uuid:generate MerchantProfile spy_merchant_profile_address
```

{% info_block warningBox "Verification" %}

Make sure the following changes have been applied by checking your database:

| DATABASE ENTITY | TYPE | EVENT |
| --- | --- | --- |
| spy_merchant_profile_address.uuid | column | created |

Make sure that `propel:install` logs ``Adding optional feature `Uuid` to the module `MerchantProfile` ``. If it logs that the feature is disabled, the configuration override of step 2 is not picked up; rebuild the class resolver cache and run the command again.

Make sure that every row of `spy_merchant_profile_address` has a `uuid` value.

{% endinfo_block %}

### 4) Generate the API resource

The resource is auto-discovered from the module; no plugin registration is needed. Generate the resource classes and rebuild the Backend API container:

```bash
vendor/bin/glue api:generate
console cache:empty-all
```

{% info_block warningBox "Verification" %}

Authenticate as a Back Office user and retrieve the profile of a merchant:

`GET https://glue-backend.mysprykershop.com/merchant-profiles/MER000001`

Make sure the response contains the merchant profile. Then [authenticate as a merchant user](/docs/pbc/all/identity-access-management/latest/manage-using-glue-api/glue-api-authenticate-as-a-merchant-user.html) and make sure that:

- `GET https://glue-backend.mysprykershop.com/merchant-profile` returns the profile of the merchant the user is assigned to.
- `GET https://glue-backend.mysprykershop.com/merchant-profiles/MER000001` returns a `403` response.

For the request details, see [Retrieve merchant profiles](/docs/pbc/all/merchant-management/latest/marketplace/manage-using-backend-api/backend-api-retrieve-merchant-profiles.html).

{% endinfo_block %}
